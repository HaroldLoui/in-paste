# 计划评审与技术验证（2026-11-09）

评审对象：`docs/PLAN.md`（v1 草案）、`ui.md`、`ui.png`。
方式：逐像素测量设计稿 + 读 egui/eframe 0.37 源码 + 写 M0 spike 实机跑通（Windows，100% DPI）。
结论：**方向可行，M0 三项决策门全部通过，可以进入 M1。** 但 PLAN 有 6 处需要按实测修正，另有 3 个风险需要在 M3/M4 前解决。

## 2. 对 PLAN 的修正（实现必须遵守）

1. **eframe 0.37 是 Ui-first App trait**：`fn ui(&mut self, ui: &mut egui::Ui, frame: &mut Frame)`（必需），`fn logic(&mut self, ctx, frame)`（可选）；旧的 `update(ctx, frame)` 不再存在。`CentralPanel::show` 也改成接收 `&mut Ui`。
2. **依赖 features 必须是 `["glow", "clipboard"]`**。`default-features = false` 时 egui-winit 的 arboard 剪贴板不启用，`copy_text` 只写进程内 fallback，系统剪贴板不更新。
3. **字体**：`default_fonts` 关闭后 `FontDefinitions::default()` 为空，必须 `ctx.set_fonts()` 手动加 msyh.ttc（face 0）+ segoeui.ttf；TTC 默认取 face 0（微软雅黑）。
4. **设计 token 修正**（实测替换 PLAN 第 5 节）：
   - window.bg `#F3F2FD`（PLAN #F4F5FD）
   - accent `#1468FD`（PLAN #1C6FFB 偏亮；设计稿实测 #176AFC / 按钮 #1066FE）
   - row.selected `#C6D9FE`（PLAN #CCDDFD）
   - preview.bg `#F6F6FD`（PLAN #F8F8FD）
   - row 底色 `#F6F6FC`，比卡片底色略亮，不能与 window.bg 混用
   - Ctrl 胶囊：**半透明深色** `rgba(30,42,70,15/255)`，不是 #E9EBF7；叠在白行 ≈ #E9EBF4，叠在选中行 ≈ #BED0F6
   - 列表：行高 88、列表起点 87（工具栏 78 + 9）、行距 89
   - 预览：430×337、圆角 16、与主窗 gap 20、左缘三角 18×40（尖端距主卡右缘 2px）
   - 底部按钮：复制 111×50 r14，footer 分隔线在卡底 -83
5. **列表最后一行必须画完再裁剪**。当前 spike 用 `if row.bottom() > list_rect.bottom() { break; }` 导致第 5 行完全不画；设计稿是 5 行（第 5 行被卡片底边裁掉一部分）。改为正常绘制 + `with_clip_rect(list_rect)`。
6. **字号**：列表标题 18（PLAN 未定）、时间 13、搜索占位 15–16、预览标题/正文 17–18（行高 34）、按钮 15–16、胶囊 13。spike 里 17/12 偏小。

## 3. 风险与已找到的对策

### 3.1 浮层抢键盘焦点（必须处理）

实测：`with_active(false)` 只能避免创建时激活，**用户点击浮层时 Windows 仍会激活浮层窗口**，主窗失去键盘焦点，搜索/↑↓/Enter 全部失效。

对策（已实测有效）：在浮层闭包里检测 `pointer.any_pressed()`，当浮层已获得焦点时向 ROOT 发送 `ViewportCommand::Focus`。日志顺序为 `preview refocus main → main focused = true`，随后复制按钮仍正常触发、键盘继续可用。

另有创建瞬间的 3 帧焦点抖动（浮层先 focused，主窗随后取回）。M1 若浮层改为"按需显示"，每次显示后都要执行一次回焦。

### 3.2 IME 与 Enter 的冲突

- 组合输入期间按 Enter 会被 IME 消费，不会误触发"复制并关闭"（实测组合 "rust" 后 Enter，主窗未关闭）。
- 提交后再按一次 Enter 才应触发复制关闭——M4 必须显式验证，并在组合状态下禁用 Enter 动作（egui 未暴露"正在组合"标志时，可用 `Event::Ime` 或 `TextEdit` 焦点 + 最近 IME 事件自行跟踪）。

### 3.3 未覆盖项

- 真实 125%/150% DPI：本机只有 100%，用 `set_zoom_factor` + 按比例放大窗口模拟，布局正确；混合 DPI 多显示器仍未测。→ **2026-11-11 已补测**：150% 主屏 + 100% 副屏，启动、选中展开、跨屏拖拽均正常，见 §6。
- 屏幕边缘翻转、下方空间不足的换位（M3）。
- 1000 条滚动性能、虚拟化（M5）。
- 透明区域点击穿透：阴影留白会吞点击，原型可接受；后续可用 `WM_NCHITTEST` 返回 `HTTRANSPARENT`。
- 失焦隐藏与浮层互斥：浮层获得焦点会让主窗失焦。本期原型不做失焦隐藏；若 M5 要加，需要"主窗与浮层都失焦才隐藏"或延时判定。

## 4. 架构决定

- **保留双窗口方案**（PLAN 决策 5 不变），浮层用 `show_viewport_immediate` 每帧驱动位置/尺寸，必须带 §3.1 的回焦逻辑。
- 主窗布局全部用逻辑点（points），窗口 `with_inner_size(868×608)`，由 eframe 按 DPI 自动换算物理像素。
- `window.rs` 职责明确为：主窗/浮层 builder、浮层位置计算、focus 策略；浮层尺寸常量 `18+430+28 × 337+56`。
- 模块结构沿用 PLAN 第 8 节，spike 代码按模块拆分后进入 M1；`icons.rs` 用 24×24 网格、2px 圆角描边重画（当前手绘的 link/image/pdf/pin/trash 均不达设计稿）。
- 状态仍按 PLAN：单一 AppState、`selected` 用 id、Command 枚举。

## 6. 实现偏差与更新（2026-11-11）

M1 起按实机观感调整了布局与窗口策略，与上文（M0 阶段的计划）存在以下差异：

1. **预览浮层改为单窗口横向扩展**（原计划：第二个 viewport）。选中行后发送 `ViewportCommand::InnerSize(1171×920 设计点)` 把同一个透明窗口加宽，预览卡画在右侧透明区。视觉上保留了 gap 20、左缘三角和独立阴影，但不再是真正的顶层窗口：预览无法超出主窗矩形，也不能独立置顶。M0 验证过的浮层回焦方案（§3.1）仍保留，将来切回双窗口时可直接复用。
2. **工具栏拆成两行**：卡片收窄后单行放不下「5 个分类图标 + 搜索 + 置顶 + 关闭」，按外部反馈改为第一行搜索 + 窗口按钮、第二行分类图标 + 下划线。
3. **尺寸整体缩小 1/3**：设计坐标改为窗口 720×920、主卡 672×816，并新增 `theme::UI_SCALE = 2/3`——布局仍按设计点计算，由 `ctx.set_zoom_factor` 与窗口原生尺寸一起缩到实际界面大小。改一处即可整体缩放。
4. **DPI 修复（本次重点）**：150% 缩放下窗口首帧只绘制左上角、点击列表后才完整。原因：`SetWindowPos` 单位是物理像素，代码却传了 `BASE_W/BASE_H` 逻辑点，窗口只有预期的 2/3。修复：首帧用 `GetDpiForWindow` 换算物理像素（再乘 `UI_SCALE`），并把 `strip_system_frame` 改为返回「本帧是否动过窗口」，动过就 `request_repaint()`。
5. **设计 token 以 `src/theme.rs` 为准**（与 PLAN 第 4 节同步）：图标块 64（设计稿实测，非 ui.md 的 56）、行高 81/首行 90、列表起点 146、搜索胶囊 58 高 r29、Ctrl 胶囊 110×42 r11、预览 431×338 r18。
6. **混合 DPI 实测**：150% 主屏窗口 720×920 物理（=设计点×2/3×1.5），展开 1171×920；拖到 100% 副屏为 781×613，展开后 781×613；拖回 150% 恢复 1172×920（±1px 取整）。截图与取证见 `.tmp/`（未入库）。
7. **仍未实现**：真实剪贴板数据、搜索过滤、键盘导航、复制/置顶/删除动作、托盘与持久化——当前原型只有「点击行 → 选中并展开预览」这一条交互。

## 7. 交互重构与窗口修复（2026-11-11）

按外部反馈重做了交互模型，并修掉两个窗口层问题。§6 中「只有点击选中一条交互」「预览底部按钮组」「Ctrl 胶囊」等描述已过期，以本节为准。

### 7.1 交互模型

1. **删除 `Ctrl + N` 胶囊**：行内不再显示快捷键提示。键盘操作已补齐：`↑`/`↓` 切换选中（自动滚动到可见），`Enter` 复制当前项并收起，`Ctrl + 1..9` 复制对应行，`Delete` 删除当前项，`Esc` 返回/收起。
2. **行内三按钮**：行被 hover **或选中**时，右侧显示「复制 / 置顶 / 删除」三个 34×34 图标按钮；复制 = 复制内容并收起面板。
3. **预览去页脚**：去掉底部按钮组与分隔线，`PREVIEW_H` 338 → 240；操作统一在行内完成。
4. **关闭按钮换成设置齿轮**：工具栏右侧为「窗口置顶」+「设置」；设置页含呼出快捷键、失焦自动隐藏开关、窗口置顶开关、退出、返回。
5. **收起方式**：点卡片/预览外、`Esc`（设置页先返回列表）、失焦自动隐藏（可关）、全局热键 `Ctrl + Shift + V`。
6. **置顶语义**：工具栏置顶 = 窗口 `AlwaysOnTop` + 失焦不隐藏；记录置顶只影响排序与图标。

### 7.2 窗口层问题与修复

1. **尺寸漂移（+22×+56/次）**：`decorations(true)` 时 winit 在 visible / 尺寸等 flag 变化后会按「有装饰」重贴 `WS_CAPTION` 等样式，而每帧剥样式没有补偿客户区 → 客户区变大 → 卡片自适应把窗口再撑大 → 死循环。改为 `with_decorations(false)` 创建。
2. **顶部 1px 亮线**：winit 无装饰窗口的客户区原点比窗口低 1px（实测 `window=(920,340)` / `client=(920,341)`），透明窗口下露成一条亮线；换 DWM 边框色、cloak 隐藏都只是绕开表象（用红色 clear_color 验证过第 0 行不由 egui 绘制）。修复：首帧 `SetWindowSubclass` 接管 `WM_NCCALCSIZE`，wParam=TRUE 时直接返回 0，让客户区 = 整窗。DPI 变化与 cloak 往返后仍有效（顶部第 0 行像素由 `#D0DEEC` 变为桌面底色）。
3. **隐藏方式**：`ViewportCommand::Visible(false)` 走 `ShowWindow`，重新显示后顶部会留 1px 条带；改用 DWM cloak（`DWMWA_CLOAK`），并按需把前台还给唤出前的窗口。
4. **样式拉锯收尾（2026-11-11 晚）**：winit 的样式重写无法靠「每帧剥掉」彻底解决，改为首帧子类化后在 `WM_STYLECHANGING` 里过滤即将写入的装饰位（并把 `WS_EX_TOOLWINDOW` 固定、清 `WS_EX_APPWINDOW`）；同时关掉 DWM 非客户区渲染并 `RedrawWindow` 清缓存帧。置顶不再发 `ViewportCommand::WindowLevel`（它同样会触发整写样式），改为直接 `SetWindowPos(HWND_TOPMOST / HWND_NOTOPMOST)`。
5. **“标题栏闪烁”主因是控制台窗口（2026-11-11 晚修正）**：抓帧 + 窗口枚举确认，闪的那条标题栏属于 **debug 构建的控制台窗口**（`class=CASCADIA_HOSTING_WINDOW_CLASS`，标题是 exe 路径），它被置顶面板挡住大半，只从面板的**透明留白**里透出来；焦点切换时控制台标题栏在激活/非激活配色间切换，看起来像我们的窗口装饰闪了一下。用 `-WindowStyle Hidden/Minimized` 消掉控制台后闪帧为 0。修复：`src/main.rs` 始终 `windows_subsystem = "windows"`（debug 也是），不再创建控制台窗口。

### 7.3 拖动与缩放

- 拖动：工具栏留白 / 卡片上下留白 → `ViewportCommand::StartDrag`。
- 缩放：四边四角 7px 热区，最小卡片 460×420（窗口 508×484）。位移用 `GetCursorPos` 的**屏幕绝对坐标** + 固定对边计算；早期用窗口内相对坐标会把「窗口移动」重复计入，出现越拉越大的正反馈。
- 首帧兜底：Ui-first 首帧的 `content_rect` 可能是 `15000×15000`，尺寸同步逻辑跳过 > 8000 的值。

### 7.4 验证

- 150% 主屏：启动 720×920；选中 1171×920；复制后 cloak 隐藏；热键唤回 720×920；失焦隐藏；置顶后失焦保持；关自动隐藏后失焦保持。
- 缩放：东边 +80 → 797×920；北边外拉 → 高度增加、位置同步；右下角内收 → 尺寸按位移减少；最小尺寸生效。
- 100% 副屏：收起 480×613、展开 781×613；cloak 往返与顶部均无亮线。
- 抓帧验证：GUI 子系统构建下，pin 点击 / 失焦 / 获焦 / 设置页来回均为 0 闪帧（修复前同一脚本稳定抓出 4–6 帧）。
- 质量门：`cargo build` / `clippy --all-targets` 0 warning，`fmt --check` 通过。

### 7.5 已知缺陷（2026-11-11）

- **标题残影（已修复）**：抓帧确认残影只有窗口标题文字（没有标题栏底板），在激活、点击置顶、焦点切换时会出现。窗口始终是工具窗、不需要标题，因此首帧初始化时用 `SetWindowTextW(hwnd, L"")` 清空标题后，激活/置顶/焦点切换均不再出现 `in-paste` 残影（2026-11-11 补丁）。
